# 《普通人用 DSH 做 Mod 有多难》视频方案（剪映）

> 目标片长 12–14 分钟｜平台 B 站｜核心命题：不是"AI 帮我写代码"，而是"我三次判断错了游戏该怎么被模拟"。

---

## 0. 一句话结论

**这个题材能成，而且比 90% 的"AI 编程"视频有优势**：你有三次真实失败、有可量化的代价（钱/天/行数）、有一个技术上的"正确洞察"作为高潮。
唯一硬伤是**前两版没有画面**——不要试图伪造，把它变成叙事结构："从只剩日志的废墟，到唯一活下来的成品"。

风险：AI 编程视频已经同质化。差异化不在"我做出了什么"，而在**"我错在哪、为什么错、第三次为什么对"**。观众看的是判断力，不是代码。

---

## 1. 叙事骨架（最重要的决定）

### 1.1 不要按时间顺序讲

按时间讲 = 流水账。用**结果前置 + 三次倒叙**：

| 幕 | 内容 | 观众获得 |
|---|---|---|
| 冷开场（40s） | 成品画面：面板给出路线 → 自动出牌 → 无伤通关；叠三个数字 | "这玩意儿真能用" |
| 第一幕 | 第一版：拿实机当模拟器 | 一个错误的信念 |
| 第二幕 | 第二版：手工复刻全部卡牌/遗物 | 一个更贵的错误信念 |
| 第三幕 | 第三版：隔离沙盒 | 洞察：**别重写游戏，复制游戏** |
| 尾声 | 对比 STS2 原版 mod + 代价清单 | 结论与可复用方法 |

### 1.2 三次尝试 = 三种"错误类型"（这是全片的脊梁）

必须让观众感到**递进**，而不是"你反复踩坑"：

1. **第一版错在"想得太便宜"**——以为"在真游戏里出牌再重置"就等于模拟。实际是把渲染、动画、存档一起卷进了搜索。病因一句话：**把"能跑"当成了"能模拟"**。
2. **第二版错在"想得太贵"**——以为把 187 个遗物、全部卡牌效果手写出来就能模拟。实际是在用数据近似规则。病因一句话：**把"数据"当成了"规则"**。
3. **第三版对在"借力"**——不重写任何一张卡，把战斗对象图深拷贝进隔离世界，让**游戏自己的代码**在副本上跑。病因一句话：**不重写游戏，只复制游戏**。

这三句话就是观众离场时能记住的东西。全片至少重复两次（第一次埋在对应章节，第二次在结尾合体）。

### 1.3 给故事一个"对手"

反派不是 DSH，也不是你菜。反派是 **STS1 的引擎结构**：Java、全局静态状态（README 记录 453 个进程级静态字段）、13 条 RNG 流、动画和逻辑长在同一根时间轴上。

这样讲的好处：失败变成"对手太强"，成功变成"找到了对手的破绽"，而不是"AI 真笨 / 我真笨"。

## 2. 分镜与流程（12–14 分钟版）

### 冷开场 0:00–0:45
- 画面：**先给结果**。战斗中的面板特写（路线 + 预计伤害）→ 自动出牌 → 最后一击 → 胜利结算。全程无解说，只有环境音 + 一下心跳。
- 45 秒处旁白第一句（见 §4）。
- 字幕打出三个数字：**¥几百 / 3 次推倒 / 57,851 行**（最后一个数字是实测：135 个 java 文件、57,851 行，可写"约 5.8 万行"）。
- 目的：3 秒内让观众知道"这是个真东西"，30 秒内知道"代价很大"。

### 背景 0:45–1:40
- 画面：杀戮尖塔 2 的 CombatSolver 演示（若可用其仓库/视频素材，注明出处）；切到 STS1 界面。
- 旁白：我在 B 站/社区看到 STS2 有战斗求解器，想让 1 代也有一个。
- 关键信息：**STS2 的 mod 需要每个 mod 自己适配卡牌**——这句一定要说，因为它是结尾"我的更好"的伏笔。
- 不要在这里讲"什么是 DSH"，一句话带过："一个能自己读代码、改代码、跑测试的 AI 编程工具。"

### 第一幕 1:40–3:30｜用实机当模拟器
- 画面策略（无原始录屏）：**重建示意图 + 真实日志**。画一张循环图：出牌 → 记录 → 重置血量和手牌 → 再出牌；旁边叠当年日志的滚动（用现在的 evidence 日志做底，注明"同类日志"）。
- 讲三个具体故障，各配一句"症状"：
  1. 重置不彻底 → 模拟从"脏状态"开始，越搜越错；
  2. 动画跟着实机播 → 怪物受击、胜利结算反复触发 → 卡顿、状态错乱、bug；
  3. 我错误指挥 DSH 做深度搜索 → 搜索路径本身可能算错。
- 收尾金句：**"我以为我在模拟游戏，其实我在直播游戏。"**

### 第二幕 3:30–7:00｜手工复刻整个游戏（国庆，最贵的一幕）
这一幕是"钱"的位置，必须做足。
- 画面：**这是你唯一有真实物证的失败**——用 `evidence/m4/t313-exhaustive-optimal/` 里的东西：
  - `relic-disposition.tsv`：187 个遗物逐条分诊表，可做**进度条动画**（覆盖 40 个 / 缺口 147 个 ≈ 78.6% 未覆盖）；
  - `REPORT.md` 标题：遗物缺口逐条分诊、"改战斗规则的遗物"审计纠正；
  - `eng-relics.json.dump`（43KB）做"数据墙"背景；
  - 两个 .java 门禁脚本 → 说明"每补一条规则都要写一个校验"。
- 讲清成本结构：卡牌效果不是"数值"，是**联动**（这张牌打完触发那个遗物再触发这个能力），手写等于把引擎重写一遍。做了四分之一，钱和时间先撑不住了。
- 数字：**187 个遗物、147 个缺口**、当时只推进到约 1/4。
- 收尾金句：**"我不是在写求解器，我是在重写杀戮尖塔。"**
- 情绪点：坦诚"这一版我删了，只剩下这些表"——真实感比任何特效都值钱。

### 第三幕 7:00–11:00｜隔离沙盒（高潮）
- 先给"顿悟时刻"：DSH 提出——STS2 之所以能模拟，是因为它**自己实现了卡牌**；那 STS1 能不能不实现，直接**借引擎**？答案：把战斗对象图深拷贝进一个隔离世界，让游戏自己的代码在副本上出牌。
- 画面：架构示意图（三层：实机世界 / 静态槽 / 沙盒副本），配一个"换血"动画（静态字段被写入副本、再写回）。
- 技术亮点按"观众能懂"的顺序讲：
  1. 不写任何一张卡的效果——**一步 = 真的调用 `AbstractCard.use`**；
  2. 453 个全局静态字段 + 13 条 RNG 流一起搬，才不会"抽牌顺序漂移"；
  3. Beam search 给路线排序，先搜最可能成功的分支（解释"为什么快"）；
  4. 执行时每步比对状态摘要，**一旦和预测不符就作废重算**（这是"可信"的来源）。
- 也要讲残留 bug（必讲，否则不可信）：沙盒没隔离干净 → 动画被复用 → 怪物动画错乱；检查不充分 → 某类战斗模拟失真。可配"泄露"示意图：两条时间轴串线。
- 这段建议配"档案墙"视觉：146 份证据日志、B13→B89 的 bug 编号快速闪过，配计数音效。

### 成品与对比 11:00–12:40
- 实录：面板操作全流程（选战斗 → 求解 → 看路线 → 自动出牌 → 中途偏离 → 重算）。
- 对比：STS2 原版 mod 需要**为每个 mod 适配卡牌**；你的方案是**沙盒模拟**，原则上任何卡都能跑。
- 别吹"更好"，说"适用范围不同"——反而更可信。

### 尾声 12:40–13:30
- 代价清单（三个数字 + 一句人话）：钱、时间、删掉的两个版本。
- 结论不是鸡汤，是方法：**"先问这东西能不能借，再问要不要重写。"**
- 最后 5 秒留一个钩子：接下来想让它支持更多 mod / 或开源。

### 如果要压到 8 分钟
删：第二幕的分诊表细节（只留 187/147 两个数）、第三幕的 RNG 细节；保留：三句病因、沙盒示意、成品实录、代价清单。

## 5. 怎么让片子"高大上"（不靠特效）

### 5.1 核心是"视觉语法统一"，不是转场花活

只定义三种画面类型，全片严格复用：

| 类型 | 处理方式 |
|---|---|
| 实机 | 轻微推镜（100%→104%，6–8s）、暗角、降饱和 10%、游戏音保留 |
| 档案（日志/表格/代码） | 纯黑底、等宽字体、青/白单色、逐行打字或匀速滚动、极淡扫描线 |
| 图形（示意/数据） | 黑底细线、只有一个高亮色（建议琥珀 #F0A500 或青 #35D0BA） |

**转场只用两种**：硬切（90%）、章节切换用一帧白闪或 2 帧故障。禁止叠化、禁止花式转场。

### 5.2 声音是质感的一半（B 站最容易被忽略）

- 一条贯穿的低频环境垫（-30dB 左右），让安静段落不空。
- 每个技术名词配一个**固定音效**（如"沙盒"= 一声金属吸气），观众会形成条件反射。
- "失败"段落固定用同一个低频撞击音——三次失败，第三次观众会提前紧张。
- 旁白：降噪 → 压缩 → 高频提一点 → 混响极小。手机麦也能救。
- 关键数字出现时，BGM 停半拍（剪映里直接切断音频轨，留 0.2s 空白）。

### 5.3 节奏硬指标

- 每 20–30 秒必须出现**一个新信息**（新数字/新画面/新结论）。
- 每 2 分钟一个**转折**（失败、顿悟、新 bug）。
- 单镜头不超过 8 秒；档案类镜头可以长，但要有运动（滚动/推镜）。
- 字幕：一行 ≤ 12 字，关键词单独高亮，不要整段念稿式字幕。

### 5.4 剪映具体做法（按优先级）

1. **关键帧推镜 + 速度曲线**：所有实机/截图镜头做 100→105% 缩放，起手缓入。
2. **复合片段**：把"档案墙"（多张日志/表格图网格排列）做成一个复合片段，整体平移，一次做好复用三次。
3. **文本动画**：数字用"打字机 + 放大回弹"，不要用花哨预设。
4. **色度抠图/蒙版**：把游戏截图里的面板单独抠出来做悬浮放大（比整屏截图高级一档）。
5. **调色**：全片低饱和冷调（色温 -8、饱和 -10、对比 +6）；成功段落回暖（色温 +6）。
6. **智能字幕 + 手动改**：自动识别后必须逐句改错，字幕错别字最伤质感。
7. **音频**：BGM 压到 -22dB 左右，旁白 -6dB，音效用关键帧做"入场即满、0.3s 衰减"。

### 5.5 封面与标题

- 封面：左半成品实机截图（面板 + 路线），右半大字"3 次推倒 / 5.8 万行 / ¥几百"，底部一行小字"普通人用 AI 做 MOD"。
- 标题候选：
  - 《我用 AI 做了个杀戮尖塔战斗求解器，失败了两次》
  - 《普通人用 AI 做 MOD 有多难：三次推倒重来》
  - 《不写一行卡牌代码，让游戏自己算最优解》

2. **现场重演（半真实，成本低）**

3. **示意重建（明确标注）**
   用统一风格的示意图重画当年的架构，画面角落常驻"示意图 / 重建"小字。不要做成"伪录屏"。

**绝对不要**：用现在的成品画面冒充当年的失败画面。观众一旦察觉，全片可信度归零。

## 7. 对你三个想法的修改建议

1. **"电影解析式"——对，但解析对象要换**
   不要解析代码，解析**判断**。每一幕只回答三个问题：我当时相信什么？证据是什么？哪一步证伪了它？
   建议每幕固定收尾句式："我以为 X，其实 Y。"（三次，句式相同，形成节奏）
2. **"每一版都展示画面"——改成"每一版都有物证"**
   第一版：没有物证 → 用示意图 + "连截图都没留"的坦白。
   第二版：有物证（分诊表、报告、dump）→ 这是全片最有质感的一段。
   第三版：唯一有实机画面 → 形成"从废墟到成品"的视觉落差。
3. **"讲述制作过程"——顺序要改**
   不要"我先…然后…最后…"。用"结果 → 三次倒叙 → 回到结果"。观众耐心只有 40 秒。

**另外四条硬建议：**
- 钱必须具体化：几百块拆成"几次充值 / 多少个晚上"，比"花了很多钱"有效十倍。
- 不要念代码，最多给 5 秒的 diff 特写。
- 保留第三版的 bug（沙盒泄露、动画复用）——完美的成功不可信。
- 结尾不要"AI 真强大"，要"判断比工具重要"，这句话才是你的差异化。

## 11. 观众可学的 6 条 agent 用法（全部来自 1,978 条真实对话，可直接做字幕卡）

1. **纠偏比写需求更重要。** 顶层 849 条真人消息，含「不要」的 105 条，长度 ≥300 字的只有 41 条（4.8%）。用户几乎从不写长需求，而是**高频指认一个具体现象**："面板最终血量比实际多 3""这次打2小偷第二回合防御打不出"。
   观众可学：能给现象就别给方案，能给数字就别给形容词。
2. **让 AI 写交接文档，而不是靠记忆续命。** 第二版全靠 HANDOVER-FOR-NEXT-AI.md 跨会话接力；用户后来自己学会了「给我一个提示词给下一个任务」。上下文一满，文档就是唯一可靠的记忆。
3. **先立判据，再让 AI 动手。** 后期用户的原话：「找到哪里模拟出问题了。不要改我先确认」「不要模型请求了，总是在这里浪费时间」。先定位再加修复，避免 AI 反复"猜一个改一个"。
4. **长任务必须分会话。** 10-29 那次 400 报错就是上下文撑爆：主会话直接跑不动，只能开新会话诊断。片子里把它做成一个"翻车瞬间"。
5. **插件是能力，不是装饰。** 16 个插件里真正干活的是：agent-teams（顶层会话 470 次建任务、217 次发消息、132 次改派——用来并行跑验证）、billion-context（上下文压缩）、dsh-usage（就是本片数据的来源）、dsh-mnemon（跨会话记忆）、genui/modlens（看图与出图）。
6. **把"我觉得对"换成"逐步比对"。** 成品之所以可信，是因为每一步都比对 digest，不符就作废重解。这是全片唯一值得反复强调的工程思想，也是"AI 写的东西能不能信"的答案。
