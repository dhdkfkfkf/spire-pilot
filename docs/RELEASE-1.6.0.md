# 1.6.0 — 右侧变成仪表盘，左侧变成旁白

这一版把面板的分工重做了一遍：**右边只放数字和像素动画，左边放一切需要读的句子**。

完整版本历史见 [CHANGELOG.md](../CHANGELOG.md)。

## 下载

- `spire-pilot-1.6.0.jar`
- 依赖：ModTheSpire 3.30.0+、BaseMod
- 适配游戏版本：12-18-2022（最终版）

## 这一版改了什么

### 1. 像素阵

进度读数不再是横向条，而是一个 10×10 的方形像素场：边长 8、缝 1，整块 89×89，在状态块里水平居中。
状态块随之从 82 长到 157（`4 + 26 + 4 + 26 + 4 + 89 + 4`），面板往下扩，顶边不动。

### 2. 洗牌点亮

格子按一张固定的 100 项排列表点亮，不是按位置。一行行填会读成「方形进度条」，散着亮才读成「一片像素
在活起来」。用固定表而不是每帧 shuffle：同一进度必须点亮同一批格子，否则截图没法解释，两个人看同一个
百分比会看到不同的图。

### 3. 呼吸与前沿闪烁

- 已亮的格子 alpha 走 620ms 正弦，周期约 3.9 秒，慢到不吵。
- 最新点亮的 2 格走 180ms 闪烁，亮度从 `0.310,0.639,1.0` 提到 `0.560,0.820,1.0`。
- 两个波频率不同，不会锁步成一块整体在脉动。
- 搜索停滞时像素仍在呼吸——它只说明「还活着」，不谎报进度。

### 4. 右侧纯数字

承诺槽从「推到战斗结束」/「3 回合最优（已降档）」/「 · 走完 4」改成 `结束` / `3回合` / `3/5回合` /
尾部 ` ·4`。右侧是仪表盘，散文归左侧。

### 5. 左侧文案库扩充

初始化 7 句、搜索 26 句、深搜 9 句、收尾 9 句、完成 6 句。1.5 秒一换，26 条要 39 秒才循环一轮，
慢速搜索时不会背下来。

### 6. 顺带收进来的 1.5.3

`1.5.3` 的两条门禁修复（S230 / S246，`passes()` 数 rung 而非药水档、`beamWidth()` 补峰值记忆）
也在这一版里，细节见 CHANGELOG 的 1.5.3 条。

## 附：1.5.3 的内容（历史，保留供对照）

### 1. `passes()` 数的是 rung，不是药水档

`passes()` 过去返回药水档的数量。没有药水的牌组恒为 1，而加宽阶梯现在跑在同一个会话里，所以「跑了几档」
应当是 rung 数。非 cell 模式下改为 `passes() = rung() + 1`，`finishAll` 也改用同一个定义 —— 结果里的
数字与面板读的数字不会再漂移。

### 2. `beamWidth()` 补上峰值记忆

`rung()` / `rungs()` 已经有峰值记忆（S245 修的），`beamWidth()` 漏了：搜索结束、`current` 被清空后它返回
`-1`，于是「加宽档在跑」这条断言读到 `beam=-1`。现在加 `lastBeam`，与 `lastRung` 同规格。

### 3. 顺带收进来的两版

`1.5.1`（进度副文案按秒轮换）与 `1.5.2`（回合数 4/5、按回合数求解不再被时间砍）也在 1.5.3 里，
细节见 CHANGELOG。

## 附：1.0.1 的内容（历史，保留供对照）

`search.horizonTurns` 的默认值从 `3` 改为 `0`：

- `0`（默认）= 不分回合截断，一直算到分出胜负、分叉跑完、或预算用完。
- 填正数 = 你自己设的硬上限，降档阶梯不会超过它。

`无限` 档没有时钟，因此不降档：一直算到你再按一次「计算」。

### 1. 预算不够才降档：3 → 2 → 1

搜索每走完一层，会看一次时钟。按预算的 **25% / 50% / 75%** 三个点：

| 已用预算 | 承诺 |
| --- | --- |
| < 25% | 推到战斗结束 |
| ≥ 25% | 最多 3 回合 |
| ≥ 50% | 最多 2 回合 |
| ≥ 75% | 最多 1 回合 |

两个约束：

- **只降没走到的深度**：如果 25% 时已经走完 4 个回合，不会把你砍回 3 回合。跑在预算前面的搜索不动。
- **降了不回弹**：一旦承诺降到 3 回合，后面不会再涨回去；只会在更晚的时间点继续降到 2、1。

日志：

```
stage: 6s of 12s used, 0 turn(s) finished; promise narrowed to 3 turn(s)
```

### 2. 半回合不是一档

阶梯只到 1 回合。半回合仍然只在单回合动作数 ≥ 20 时交付——那时凑满一整回合的克隆代价已经超过收益。少于 20 个动作时，收尾会用「真正走完过回合」的最好一条线顶替半截线。

### 3. 面板跟着说人话

- 开头：`推到战斗结束 · 已走完 N 回合`
- 降档后：`追求 3 回合最优（已降档）`，详情写 `（预算不够，从推到战斗结束降到 3 回合）`
- 规划结论行同样保留这句话，关掉面板再打开也还知道这条线是在什么承诺下算出来的。

### 4. 顺带修掉的两处耦合

默认值从 3 变成 0 之后，有两处逻辑是用「上限非 0」当「玩家会话」的代名词，会一起失效，已改为按「有没有时钟」判断：

- `自动` 档的「牌越打越多就延长预算」原本要求上限非 0，否则不再生效。
- 「输线补到战斗结束」原本按上限为 0 判断，否则会越过预算硬补。

### 5. 构建脚本

`tools/build.ps1` 里 `javac -version` 把版本写到 stderr，被 `$ErrorActionPreference='Stop'` 当成致命错误，导致构建在第一步就红。改为经 `cmd` 取版本，构建输出不再带错误记录。

## 开关一览

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `search.horizonTurns` | `0` | 回合硬上限；`0` = 推到结束（没有显式上限时才走降档阶梯） |
| `search.targetFocus` | 开 | 单体牌只保留关键目标 |
| `search.turnPlan` | 开 | 回合级候选排序 |
| `search.diversity` | 开 | 束宽动作类型多样性 |
| `search.dominance` | 关 | 同层格挡更少的状态直接丢 |
| `search.symmetricTargets` | 关 | 合并外观完全相同的怪物 |
| `panel.timing` | 关 | 状态行显示本帧耗时 |

## 升级

直接用 `spire-pilot-1.6.0.jar` 覆盖 `mods/spire-pilot.jar` 即可，不需要改配置。
`settings.txt` 里如果手动写过 `search.horizonTurns=3`，那是你自己的硬上限，本版会照旧遵守；想恢复默认行为请删掉这一行或改成 `0`。

## 已知边界

- 预算内最好不等于全局最优；手牌与怪物极多的局面仍可能只覆盖半回合（动作数 ≥ 20）。
- 未展开的分支会在面板底部列出，那些分支上的路线不一定最优。
- 纹理守卫只阻止「空纹理崩溃」，被替换的位置显示占位图，不影响结算。
