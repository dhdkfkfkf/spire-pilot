## 2. 剪映工程设置（先设好，后面不用改）

- 新建项目：**1920×1080 / 30fps**（素材 60fps 也放 30fps 时间轴，剪映会自动抽帧）
- 主色：背景 `#0A0A0A`；文字白 `#F2F2F2`；强调色 **`#E8503A`（红）**；次强调 `#F5C542`（黄，只用于数字）
- 字体：**微软雅黑 Bold**（标题 96px / 字幕 54px / 角标 32px）。不要用花字，全片一种字体
- 轨道结构（固定，别乱）：

```
V3  角标 / 时间码 / 小字注释
V2  图卡 / 字幕卡 / 数据动画（我出的 PNG）
V1  主画面（录屏）
A1  旁白（我出的 MP3，按句切好）
A2  BGM（-22dB，全片一条，转折处 ducking）
A3  音效（键盘声、数字滚动声、静音点）
```

- 转场只用 3 种：**硬切**（默认）、**白闪 3 帧**（章节切换）、**推近 105%**（强调）。禁止叠化、禁止翻页
- 全片加一层：**暗角 15%**、对比度 +8、饱和度 −5。这一步让画面"变贵"

## 5. 省 token / 省时间的 8 条硬规矩（照做能省一半）

1. **需求一次说全**。要改就说"第 3 段旁白重写，理由 X"，不要一句一句挤。
2. **只给截图，不给录屏**。图像输入最贵，一段 10 秒录屏不如 1 张关键帧。
3. **图卡走模板**。要改就说"所有卡片标题字号 +8"，不要一张一张点。
4. **长文本落盘**。不要在对话里贴 3000 字，写成文件让我读。
5. **每 50–80 轮重开一个会话**，用本文件交接。会话越长，每轮越贵（平方增长）。
6. **先定稿再配音**。TTS 免费，但重剪不免费。旁白定稿后一次性生成。
7. **返修打包**。攒 10 条一起提，不要 1 条跑一次。
8. **不要让我"看"视频**。要我判断画面，给静帧。

## 9. 素材实测与逐段剪辑点（2026-11-11 收到 8 个 MP4）

### 9.1 分辨率：720p 够用，不必重录（2026-11-11 实测纠正）

8 个文件统一 **1280×720 / 30fps / 带音轨**。早先判断"面板字太小必须重录 1080p"，实测否定：
- 面板主行文字原图**约 20px 高**（不是 8–10px）；放大 1.5 倍进 1080p 工程 = 30px，与 54px 字幕同屏可读。
- 即使裁左上 780×280 再放大 2.5 倍做特写，文字边缘略软但仍能读。
- **结论：全部 720p 直接用，不重录。** 唯一约束是不要做超过 3 倍的推近。

模拟效果图：_tmp\frames\sim-1080p.png（整帧 1.5 倍 + 54px 字幕）、_tmp\frames\sim-crop.png（裁切 2.5 倍）。

面板特写还有个便宜办法：裁切后叠一层细扫描线 + 轻微噪点，把"软"伪装成"监控录像"，观感反而成立。

### 9.3 由实测得到的三条剪辑结论

1. **静止段就是节奏**：战斗1 前 24 秒、战斗2 前 43 秒全是"在算/等回合"，原样放观众 10 秒就划走。删掉它们，45 秒素材能变成 20 秒高密度打斗。
2. **击杀帧要单独抠**：战斗2 的 78s 是关键一帧，剪映里定格 1.5 秒 + 一声闷响 + 轻微震屏，比任何转场都有效。
3. **面板必须放大**：720p 原尺寸面板主行文字约 **20px**（此前误估 8–10px）；整帧放大 1.5× 进 1080p ≈ 30px，与 54px 字幕同屏可读；裁左上 780×280 再放大 2.5× 也可读但边缘略软。**8 段 720p 素材全部直接用，不必重录**；唯一约束是推近不超过 3 倍。

## 11. 整片自动合成（2026-11-12）

### 11.1 为什么用程序合成，不用剪映手剪

39 个镜头、45 句旁白、每 6–10 秒一次画面切换，手剪要 15–25 小时，且改一句文案就要重剪。改成 **Python 逐帧绘制 + ffmpeg 编码**：

- 字幕位置、字卡折行、字幕与画面的时间对齐全部由代码保证，改文案只改一处字符串。
- 同一条时间线一次输出**横屏 1920×1080** 和**竖屏 1080×1920**两个版本。

## 19. v6：镜头顺序纠正 + 静图平滑推镜（2026-11-13）

### 19.1 旁白与画面错位的真实原因

### 19.2 卡顿根因与修法
- 旧 `shot_frames` 用「每帧重复 hold 次」实现慢放：`speed=0.5` → 每帧重复 2 次（等效 15fps），`speed=0.1` → 重复 10 次（等效 3fps）。所以画面一格一格跳。
- 新实现：`-vf "setpts=PTS/{speed},fps=30"`，hold 恒为 1 —— 但**源只有 30fps，慢放 2 倍必然只有 15 个不同画面**，重复帧无法靠滤镜消除（除非 minterpolate，会对屏幕文字产生鬼影）。
- 因此两个镜头都改成 **still（静帧）**：
  - `still_frames(sh,W,H,mode)`：ffmpeg 取一帧 → 按 `c` 裁切 → 每输出帧用 `Image.transform(AFFINE)` 做**亚像素**采样（缩放 + 平移），30fps 连续、无双帧。
  - 参数：`c` 源窗口、`pan{z0,z1,zt,cx,cy0,cy1}`、`hb`（横屏占高比）、`tmax`、`sharp`、`label`/`cap`。
- 用量镜头：`s=6.2`（近30天干净窗口）`c=[340,96,800,462]`、`tmax=1130`、`z 1.0→1.06`，慢推近；不再录制鼠标移动/下拉。
- 插件镜头：`s=0.2`、`c=[344,84,602,602]`、`hb=0.82`（画面高 886px，比原来 452px 窗口大约一倍）、`z 1.0→1.07` 极缓推近。

### 19.3 最终取景参数（v6 定版）
- 用量：`still`，`s=6.2`，`c=[362,96,770,462]`，`tmax=1140`，`z 1.0→1.06`（占宽 1140px，约为老的 1.0 倍但不再抖）。

### 19.4 剪映里等价的正确做法（给观众/复用）
1. 屏录素材若录的是 30fps，**不要靠剪映「变速」慢放到 0.5× 以下** —— 那只是把同一帧重复显示，等效帧率减半，必然一卡一卡。
2. 正确做法：把要展示的画面**定格成一张图**（右键 → 定格，或导出单帧），再对这张图打**关键帧**做缩放/位移。剪映对静态图的关键帧插值是逐帧计算的，30fps 连续，不会跳。
3. 如果必须保留画面内的鼠标动作：素材用 60fps 录屏，再慢放到 0.5×（仍有 30fps），或干脆按 1× 播放、只加缓慢推镜。

## 21. v8：抖动根因修复 + manim 接入（m02578）

### 21.1 抖动根因（已实测，不是观感问题）
- 旧 `_draw_zoom`：每帧都用 `(W*z, H*z)` 的**不同尺寸**重画字卡 → 字形栅格每帧重新排版，产生 1px 级 shimmer（“莫名的抖动”）。
- 中间方案：固定尺寸画 + 整数裁切 → 仍有整像素跳格（mean=0.562 / max=0.685 / std=0.067）。
- 最终方案（已落地 film.py）：`_SS=1.0`，先以 `(W,H)` 画一次；`k=1/z`，`step=SW*k/W`，`ox=(SW-SW*k)/2`，`oy` 同理；`im.transform((W,H), Image.AFFINE, (step,0,ox,0,step,oy), resample=Image.BILINEAR)` —— **亚像素仿射**缩放，不重排字形。
- 帧间差实测（纯静态字卡 cw，30 帧）：旧 0.737/1.826/0.340 → 裁切 0.562/0.685/0.067 → **仿射 0.298/0.317/0.0115**（均值降 2.5 倍，标准差降约 30 倍）。稳态耗时 116ms/帧。
- 结论：微动保留；若仍嫌抖，唯一彻底方案是整片关掉统一微动（`ZOOM=0`），不做第三种折中。
