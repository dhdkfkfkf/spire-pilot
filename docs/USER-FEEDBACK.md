# 用户反馈与处理记录

这个文件记录玩家报告的问题、复现条件与当前状态。状态只有三类：

- **已修**：有版本号、有门禁或明确的行为变化；
- **待取证**：现象成立，但缺少复现所需的信息（mod 名称、具体界面、触发场景），不盲改；
- **已知边界**：设计如此，写清楚原因，避免反复返工。

## 待取证

### F1 自定义 GRID 选牌界面在自动战斗中还要点一次「确定」

- **反馈原文**：「mod 有自定义选牌界面 GRID 时，自动战斗中还需要点一次确定，这点能否更新优化一下」。
- **现象**：装了提供自定义选牌（GRID 布局）界面的 mod 后，自动/半自动执行到需要选牌的步骤时会停下，
  等玩家手动点一次确认，之后才继续。
- **为什么还没有自动点**：选牌界面是**真实的搜索分支**，不是可以随便关掉的弹窗。面板按界面给出的
  选项逐一推演，选中的那一个写进路线；玩家确认的点，同时是「路线里已经选了什么」的校验点。
  对不认识的界面盲目点「确定」，可能替玩家做出与路线不一致的选择，比停下来更糟。当前实现对
  记不下选项的界面会**跳过该分支**并在面板底部点名（「未展开…」），而不是猜。
- **修复需要什么**（玩家或复现者提供任意一项即可推进）：
  1. 提供该选牌界面的 mod 名称与创意工坊链接；
  2. 截图该界面（能看到按钮与卡牌布局）；
  3. 用面板的「导出报告」生成 zip（日志尾部 + 设置 + 版本 + 路线，不含存档与个人信息）。
- **状态**：挂起。没有 mod 名称与界面类型时，无法区分「普通的 GRID 选牌（应可自动）」与
  「mod 自定义的确认流程（需要专门适配）」。

## 怎么报告

- Steam 创意工坊条目 `3841766487` 的评论区，或
  [GitHub Issues](https://github.com/dhdkfkfkf/spire-pilot/issues)；
- 附上：游戏版本、ModTheSpire 版本、问题 mod 的名称/链接、复现步骤；
- 最好附面板「导出报告」的 zip（`%USERPROFILE%\spire-pilot\reports\`）。报告里用户目录会被替换成
  `%USERPROFILE%`，不含存档；**请不要发送存档或个人信息**。

## 处理原则

1. **先复现，再修**。没有 mod 名与触发场景的报告，先记录、不猜实现。
2. **默认行为不因一条反馈改变**。需要改变默认值的修复，先做成 opt-in 开关，并在
   `docs/VALIDATION.md` 里写清验收门禁。
3. **已知边界写进文档**，包括本文件、README 的 Limits 一节与发布说明，减少重复解释。
4. 修复必须带门禁；只有「跑起来没问题」不算验收。
