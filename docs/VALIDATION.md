# 验证体系：门禁怎么跑、证据长什么样

Spire Pilot 的所有验证都在**真实游戏里**完成：真实引擎、真实战斗、真实结算。没有 mock，
没有「理论上应该对」。本文说明验证的层级、证据纪律，以及做搜索实验时额外遵守的规则。

## 1. 三层验证

| 层 | 入口 | 内容 | 何时跑 |
| --- | --- | --- | --- |
| 全量套件 | `tools\run.ps1` | 846 项自动化检查，在游戏主菜单构建真实战斗并逐项断言 | 每个版本发布前 |
| 定向门禁 | `tools\run.ps1 -Gates "S290,S291"` | 按编号只跑相关门禁，每项打印期望值与实测值 | 改动涉及哪块就跑哪组 |
| 内容覆盖 | `tools\run.ps1 -Mode coverage [-AllMods]` | 541 张卡、46 瓶药水、210 个遗物、67 只怪物逐个真实执行 | 内容相关改动、大版本 |

发布门禁至少包括 `S270,S276,S277,S278`（安装包、版本、动作枚举完整性、判等严格性），
再做与本次改动直接相关的门禁。1.7.0 的搜索线额外跑了 S283–S293，见
[EXPERIMENTS.md](EXPERIMENTS.md)。

## 2. 证据纪律

每一次「实测通过」都必须同时满足下面几条，否则不算证据：

1. **被测 jar 可追溯**：记录构建产物的 sha256、字节数、构建分支与提交；安装进游戏的
   jar 必须与构建产物同哈希。
2. **官方 jar 可还原**：每次临时换入被测包之前先备份，跑完恢复并复核官方包哈希
   （1.6.10 官方包为 `a2dde76e…`），同时确认没有残留 `java.exe`。
3. **原始输出落盘**：控制台整段重定向到文件（每轮一个 `raw-*.txt`），门禁失败时同时保留
   期望值与实测值。游戏日志会轮转，不作为唯一证据。
4. **数字来自运行，不来自推断**：门禁里的期望值来自上一轮已验收的跑分；任何一次改动后
   必须重跑并逐项对照，而不是「代码没碰这块，应该没变」。
5. **默认行为用等价性证明**：新增 opt-in 开关时，默认分支必须与改动前逐字节一致。做法是
   在门禁里放「默认臂」和「已知对照臂」，默认臂复现历史数字（例如 S290 默认行 = S289
   早停开行），off/on 臂复现各自的目标行为。
6. **确定性复核**：同一夹具在聚焦与全 mod 环境下跑，nodes / bestAt / score 必须逐格相同
   （S283 已验证 54 格相同）。这保证分数差异来自改动，而不是环境。

## 3. 搜索结果的可比性规则

搜索输出里最容易误用的是 `plan=` 哈希。它包含每进程重建的卡牌 UUID，**跨进程不可比**；
同一进程内、同一夹具+seed 的 `planSameAsV0` 才有效。跨运行比较只用：

- `score`：最终最好分；
- `nodes`：总节点（注意 cap 封顶时按构造相等）；
- `bestAt`：最终最好分首次达到的节点序号；
- `steps`：最好线步数；
- `proven`：是否因零成本胜利触发早停。

同分不代表同线，判线用步骤内容，不用分数。20k 预算下的「最优」只在该预算内成立
（S285 已证明 9301 在 80k 还能 +5,997 分）。

## 5. 未覆盖与已知边界

- **早停损失只在 Feed 夹具上测过**。没有种族的回血/成长时，早停没有可测代价；其他成长
  来源（如遗物）是否同样被漏掉，未单独测量。
- **药水/遗物薄碰撞**只测量了「空槽 vs Fire Potion」「Nunchaku 0 vs 7」两类；球只做了代码
  核对（缺 evoke/passive），未构造 Defect 夹具。
- **硬夹具只有一个**（F4）。F5–F7 的失败说明「加怪/加药水」不等于「变难」；1.8 需要先
  扩充夹具，再做保留策略实验。
- 门禁无法覆盖「每个 mod 的每种选牌界面」；读不全的情形表现为一次重算，日志标记为
  `incomplete legal action set`。

## 6. 常见误读

| 误读 | 实际 |
| --- | --- |
| 「S292 红了，搜索坏了」 | S292 是硬度闸，红代表夹具不够难，不代表搜索回归 |
| 「20k 下 V1–V3 没差别，所以开关无用」 | 只能说明在这些夹具/预算下未触发，见 S285 |
| 「V4 在 9303 上 +18,000，可以当默认」 | 同一夹具 9301 −12,798、9302 −7,987，方向相反 |
| 「关掉 diversity 就是去掉探索」 | 本项目不是 MCTS；diversity 是按动作类保底的 beam 择优 |
| 「默认臂没变，就不用跑」 | 默认臂必须靠门禁复现历史数字，不能靠推断 |
