# 来源、许可与原创边界

这份文档不是在法律声明之外再加一份，而是把「哪些来自上游、哪些是本仓库自己的工作」写清楚。
完整的许可证原文见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。

## 1. 项目血统

Spire Pilot 是 [STS1 Engine Solver](https://github.com/zck070718/sts1-engine-solver)
（作者 闪珖灵感菇，MIT）的**直接衍生作品**：源码基线、沙盒镜像、搜索与执行校验、面板与
路线展示都来自该项目 1.0.3 及之后的上游版本。整体求解流程的架构（抓取根状态 → 隔离副本
模拟 → 输出路线 → 原生入口执行 → 摘要比对、偏离即重算）参考
[CombatSolver](https://github.com/Torch1230/CombatSolver)（作者 Torch，MIT）。

我们没有把上游的工作说成自己的：本仓库的 `CHANGELOG.md` 从 0.1.0 开始逐项记录每一次改动，
`THIRD-PARTY-NOTICES.md` 保留两段 MIT 声明原文。

## 2. 本仓库自己做的部分

以下内容来自本仓库的版本线（0.1.0 起），不是上游 1.0.3 自带的：

- **纹理守卫收口为单一总闸门**：贴图加载失败时跳过或替换，而不是在 `SpriteBatch.switchTexture`
  抛空指针崩游戏；
- **回合上限只允许时钟收窄**、按预算降档的秒数/节点阶梯、阶段降级、整回合交付、目标后置、
  可重算；
- **回合级排序与束宽内按动作类的多样性保底**（即面板里的「平均分布」）；
- **面板重做**：状态条、chip、动作三层、折叠态、全自动模式、并行计算（预取器与调度器）、
  像素网格进度条、说人话的停止原因；
- **兼容实验模式**（战斗事件 / 战斗之外两组钩子开关）、徽章尺寸修复、1.6.9 的「先杀小偷」、
  1.6.10 的动作枚举完整性闸门；
- **搜索状态审计与实验线（1.7.0）**：
  - `bestAt` / `bestUpd` 收敛指标与分数-节点曲线；
  - 硬夹具 F4–F7 的构建与硬度判据；
  - 搜索键薄碰撞的证明（药水槽、遗物计数、球 evoke/passive）；
  - 零成本早停损失 ~12,000 分的原因分解（成长 ≈6,001、战后回血同量级）；
  - 两枚默认不变的开关 `search.provenStop` / `search.keyExtras`；
  - 门禁 S283–S293 与 `docs/EXPERIMENTS.md` 的完整实验档案。

实验线的方法、数字与被否掉的假设都公开在 [EXPERIMENTS.md](EXPERIMENTS.md)。其中多个结论是
**否定的**（RNG 入键、dominance、turnPlanOff、「连续无改进就停」的早停、20k 即最优的假设），
我们把这些失败也留在档案里，因为它们和成功的结论一样是证据。

## 3. 我们不声称的部分

- 不声称引擎镜像、沙盒安装、克隆器、路线面板是原创——它们来自上游；
- 不声称「兼容所有 mod」。求解器调用游戏自己的代码，因此理论上随 mod 内容自动生效，
  但重写战斗规则（伤害公式、行动队列、回合结构、抽洗牌顺序）的 mod 可能偏离，文档与
  面板都会如实说明；
- 不声称实验数字可以脱离夹具复现。所有分数都绑定夹具、seed、预算与 jar 哈希；跨进程的
  `plan=` 哈希不可比。
