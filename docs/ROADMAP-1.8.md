# 1.8 计划：预算与保留策略（在 F4 上）

> 状态：计划，未实现。1.7.0 不含本文的任何行为改动。
> 依据与所有数字见 [EXPERIMENTS.md](EXPERIMENTS.md)。

## 1. 为什么下一轮动「预算/保留」，而不是继续动键

1.7 的 9 轮实验把四个种子层面的开关都测到了否定结论：

- RNG 入键（V1）、dominance（V2）、turnPlanOff（V3）在 F1–F3 和 F4 上都**逐位相同**；
- targetFocusOff（V4）、diversityOff（V5）在 F4 上首次出现真实差异，但**同一夹具内方向相反**
  （9303 +18,000 同时 9301 −12,798 / 9302 −7,987），不能当默认；
- 键的正确性缺口（药水槽、遗物计数）已经用 opt-in 开关修好，且在 80k 曲线上**不改变最优分**。

真正剩下的量级更大的问题在别处：**搜索的预算和 beam 保留策略决定了什么时候丢节点**。

- F2/9302 直到 19,199 节点（20k 预算的 96%）才达到最终分；
- F2/9301 在 80k 的第 72,343 个节点还能 +5,997 分；
- F4/9403 需要 33,270 节点才收敛，20k 会截断它；
- 另一方面，F4 的大部分质量在 2k–4k 节点内已经拿到，V5 在 9403 上多烧 13,231 个节点却没有
  收益。

所以 1.8 的问题写成一句话：**在不让任何 seed 丢掉最终最好线的前提下，能不能少生成节点，
或者同样节点下拿到更高分。**

## 2. 三个候选机制

每个候选都必须默认关、可门禁验收、跨 seed 稳定；任何一项达不到就不进默认。

### H1 自适应节点预算

停止条件从「固定 N 节点」改为「最终分在连续 L 个检查点内没有提升，且剩余层的上界不足以
再提升」。检查点按节点数等距（例如每 2k 一个），L 与提升阈值写成设置项。

- 已知反例必须覆盖：F2/9302 的最后一次提升就在搜索末尾，因此 H1 在早期版本里**不能**用
  「若干层无改进」；必须带「剩余层上界」才可能安全。
- 验收：F2 三 seed + F4 三 seed，默认 on 时 final score 与 off 完全相同，且 nodes 至少在一个
  seed 上下降 ≥20%；任何一个 seed 掉分即否决。

### H2 保留策略：按结果特征而非动作类别

现状的 diversity 是按动作类保底（每类先留最好节点，再按分数填满 beam）。H2 改为按**结果
特征**分组保底：击杀、格挡、保留资源、改变敌方意图等各组至少留一个代表，再按分数填。

- 理论依据：V5（直接关掉多样性）在 9403 上多烧 13k 节点、在 9301/9302 上分差方向相反，
  说明「按动作类保底」本身不是问题，问题可能是**保底选错了维度**。
- 验收：F4 三 seed，任何 seed 的 final score 不低于 V0，且至少一个 seed 的 `bestAt` 提前
  ≥30% 或 nodes 下降 ≥20%；默认关。
- 这是实验性最强的一项，允许失败；失败后记录在 EXPERIMENTS.md。

### H3 beam 宽度与层的联动

当前 beam=24、maxLayer=96 固定。H3 按「本层已生成的合法动作数」和「最好分与 beam 门槛的
差距」动态调宽：分歧大的层加宽，收敛的层收窄。

- 风险：改变 beam 成分会让不同 seed 的结果线变化，不能只比较分数。验收必须比较 steps 与
  逐 seed 的最好线等价性（同进程内 `planSameAsV0`）。
- 已知数据：F4/9401 的 V4/V5 在 2k 节点内就超过 V0 的最终分，而 9402 的 V4 反而掉 5,995——
  动态宽度必须解释这种双向性，否则不动。

## 3. 夹具计划

先扩充夹具，再跑机制实验：

1. **F4 扩 seed**：9401–9403 之外加 9404–9406，验证 V4/V5 的双向差异不是 seed 偶然；
2. **F8**：F4 怪物 + 一组会产生成长/回血的牌（Feed 或遗物），但不放药水——把早停的成长
   缺口带进硬夹具，同时避免药水缩短战斗；
3. **F9**：双意图切换的怪物组合（JawWorm + Cultist 的变体），目标是 `bestAt` 出现在总节点
   50% 之后；
4. 所有新夹具先过 S292 式硬度闸（bestAt > 8000、8k 阈值分 < 终分、V4/V5 有差异，≥2/3），
   不过闸就记录 `hardSeeds`，不按 seed 调参。

## 4. 门禁与验收

- 新门禁编号从 S295 起；
- 每个机制单独一道门禁：默认关时的行为必须与 1.7.0 逐字节一致；打开时逐 seed 记录
  `score / nodes / bestAt / steps / proven / vsV0`；
- 「不丢线」是硬条件：任何 seed 的 final score 低于基线即 FAIL；
- 「更少资源」是软条件：至少 2/3 seed 的 nodes 或 bestAt 下降 ≥20% 才允许讨论进默认；
- 默认值的变更需要：硬条件全绿 + 软条件达标 + 换一组 seed 复现（防止对 seed 过拟合）。

## 5. 非目标

- 不引入 MCTS/UCB 或随机探索：当前系统的瓶颈是状态生成与保留，不是探索率；
- 不改变评分公式与兑换率（S53 钉住的 1 HP = 2000 等）；
- 不复活已删除的指纹基础设施（快照、ExpectedTransition、动作意图）；
- 不为「难」而堆怪：F5–F7 的失败证明加怪/加药水不等于难；
- 不改 `search.provenStop` / `search.keyExtras` 的默认值——它们是正确性开关，不是效率开关。

## 6. 预期产出

- 至多一个默认变更，且必须满足第 4 节的全部条件；
- 若三个机制全部被否，1.8 的搜索部分与 1.7 相同，只带夹具与仪器——这也是一种可接受的结论。
