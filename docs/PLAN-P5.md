# P5 跑图驱动：单独计划表（v6，2026-10-30）

> **这是跑图驱动的唯一计划表。** 论证与取舍过程在 `docs/RUNMAP-PLAN.md`（§1–§11），总表只留一行指向本文件。
> 状态口径：`⬜ 未开工` / `🟡 进行中` / `✅ 完成（套件 N/0，门禁 Sxx）` / `❌ 否决（理由）`。
> 每完成一个任务：构建 → AUTOTEST 门禁 → 安装 → `evidence\P5-*.txt` → 本表勾掉 + 填卡号。

## 0. 目标与输出（先看这一节）

**本块要解决的问题**：战斗已经从「能不能赢」变成「怎么赢最省」，但**出了战斗就没人管**——走哪条路、选哪张牌、事件选哪个、营火睡觉还是锻造，全靠玩家自己。

**主输出 = 当前节点「下一步该做什么」**，不是一条整幕长路线：

```
第 7 层 · 普通怪房 · HP 58/80 · 金币 120
  左  普通怪   预计 -3 HP（实测）后 2 步有营火 +12   综合 +9   ← 建议
  中  ?        已算出=事件（第 3 个 ?） 预计 -1 HP    综合 +5
  右  精英     高风险（HP 58%）预计 -14 HP / 遗物      综合 -4
```
点「看理由」给分项；整幕长路线是同一个 beam 的副产品，展开才看。

**玩家中途接管**：任何时刻回到这张屏，**从当前节点重算**，不需要历史状态（用户 m10713 第 3 条原话：「玩家可能自己走一半让你开始走」）。
**事件/选牌/营火/商店屏同格式**：推荐哪一个 + 一句话理由 + 折算后的一个数 + 代价。
**不做的**：不预测牌序、不偷看 ? 房间真实类型（用游戏自己的 roll 算，不算幽灵信息）、不重写流程、不引入第二份战斗判定（JUDGMENT R10）。

## 4. 验收（整块做完再看，逐条能不能证明）

| # | 标准 | 怎么验 |

## 5. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 逐屏点击（P5-5）比估计更脆：mod 自绘屏/事件变体认不出 | 高 | 认不出就**只给建议不点**（降级为 M2），日志留「未知屏：<类名>」 |
| 实测掉血把界面卡住 | 中 | 分帧（2.4）先落地；每帧上限 8 ms，算不完就先用 L1 静态账 |
| mod 角色的牌/机制让 E[掉血] 偏乐观 | 中 | 估计用真引擎跑，不用数值表；拿不到胜线按高风险 |
| `?` 精算依赖内部随机状态，版本/其它 mod 改动会变 | 低 | 门禁 1.2 用实机进入类型逐一对照，不一致立即失败 |
| 存档安全 | 低 | 复用 B25 `PlayerPrefs`（模拟写沙盒）+ `tools\run.ps1` 快照；整局只在真机跑一次做 evidence |
